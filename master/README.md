# 出退勤検索くん — master.html 方式

5つのアプリ（学園前A・生駒・BA・C・予備）の index.html は、
**すべてこの master.html から作られています。**

各アプリの index.html を直接編集しないでください。
直接編集すると、次に生成したときに上書きされて消えます。

---

## 1. ファイルの役割

| ファイル | 役割 |
|---|---|
| `master.html` | **画面の本体。修正はここだけ。** アプリごとに違う値は `{{ }}` で書いてある |
| `master-manifest.json` | ホーム画面への追加の設定（アイコン・名前・色）の雛形 |
| `master-sw.js` | Service Worker（キャッシュ・更新検知）の雛形 |
| `master-share.html` | 共有ページの雛形 |
| `apps.json` | 5アプリの違いを書いた表（色・番号の上限・ダイヤ名など） |
| `build.py` | 上の雛形に apps.json を差し込んで、アプリごとに4ファイルを作る |
| `README.md` | このファイル |

**アプリのリポジトリ側で直接編集してよいのは `logs.html` とデータ・画像・PDFだけです。**
`index.html` `manifest.json` `sw.js` `share.html` の4つは生成物なので、
直接編集しても次の生成で消えます。

---

## 2. 直すときの手順

1. `master.html`（または他の雛形）を直す
2. `master.html` の中の「バージョン 2.xx」を上げる
3. `python3 build.py bump` を動かす
   → `out-<リポジトリ名>/` が5つでき、中に4ファイルが入る
4. できたフォルダの中身を、そのまま各リポジトリの直下に上書きする

`bump` を付けると、キャッシュの版番号（`a-shukkin-v112` の 112）を
**build.py が自動で1つ繰り上げます。** 手で上げる必要はありません。
上げ忘れると更新が届かない、という失敗はこれで起きなくなりました。

版番号を据え置きで作り直したいときだけ `python3 build.py`（bump なし）を使います。

## 4. ファイルの置き場所（5アプリ共通）

ダイヤ改正のときは、**同じ名前で上書きするだけ**です。
ファイル名にアプリ名は入れません。

```
dia-<id>.json        勤務データ（id は a / ikoma / ba / c / yobi）
pdf/shift-table.pdf   出退勤表PDF（無ければボタンは自動で隠れる）
pdf/kinmu-keitou.pdf  勤務系統表PDF（同上）
images/genpage-1.jpg  出退勤表の画像（2枚目以降は -2.jpg -3.jpg …）
icons/icon-*.png      アイコン8サイズ（72/96/120/144/152/180/192/512）
logs.html             更新履歴（各アプリで自由に書ける。master とは無関係）
```

画像の枚数は `apps.json` の `PAGES` で指定します。

---

## 5. 勤務データ（dia-*.json）の形

5アプリすべて同じ形です。

```json
{
  "meta": { "name":"…", "code":"a", "repo":"…", "cycle":92,
            "baseDate":"2026-05-03", "baseDial":36, "revision":"2026-03-14" },
  "holidays": ["2026-01-01", …],
  "obon": ["2026-08-13", …],
  "dials": {
    "1": { "平": {"o":"5:30〜17:35","w":"9:54"},
           "土": {"o":"…","w":"…","n":"備考"},
           "日祝": null },
    "5": null
  }
}
```

- `o` … 出退勤時間 / `w` … 労働時間 / `n` … 備考（無くてよい）
- `null` … 公休（番号ごと、または曜日ごと）
- 曜日区分は **平・土・日祝** の3つだけ

### 分割勤務（中間解放）の並び

```
"o": "6:15 / 12:25〜17:21 / 21:07"
      出勤   解放開始  解放終了  退勤
"w": "5:18 / 3:33"
      前半    後半
```

**前半 = 出勤 → 解放開始、後半 = 解放終了 → 退勤。**
拘束時間と労働時間には差があります（休憩の控除とみられる。前半0〜52分、後半0〜95分）。
**分割勤務の表示を触るときは、必ず算術的に検算すること。**

### 注意（2026-08-25 に修正済み）

以前、生駒とBAのデータだけ勤務が配列 `[{…}]` で包まれていました。
中身は全件1個だけだったので、包みを外して他と揃えました。
`meta.format` も削除済み（どこからも使われていませんでした）。

## 6. apps.json の項目

| 項目 | 意味 |
|---|---|
| `ID` | データ名や保存キーの頭（a / ikoma / ba / c / yobi） |
| `ABBR` | ホーム画面での略称（学A / 生 / BA / C / 予） |
| `DIA_NAME` | 画面に出るダイヤ名 |
| `DIA_FULL` | 画像の説明文などに使う名前 |
| `MAX` | ダイヤ番号の上限 |
| `PAGES` | 出退勤表の画像の枚数 |
| `COLOR_DARK` / `COLOR_LIGHT` | 主色（暗いテーマ / 明るいテーマ） |
| `GREEN_*` `ORANGE_*` `TEXT_*` `BORDER_*` | その他の色 |
| `ON_CYAN` | 主色の上に乗せる文字の色 |
| `BAND_BG` / `BAND_TX` | 今日の勤務の帯の色 |
| `SPLASH_BG` | 起動画面の背景色 |
| `SOON_*` | 出勤1時間前の点滅の色 |
| `REPO` | 自動で入る（書かなくてよい） |
| `SWVER` | sw.js から自動で読む（書かなくてよい） |

## 7. 決まりごと

- **場当たり修正はしない。** 直す前に、まず全アプリの差を機械的に洗い出す
- **commit / push の前に必ず変更内容を報告して確認を取る**
- **分からないことは推測で進めず、正直に「分からない」と言う**
- コミットメッセージには `(by AIタケタニ)` を付ける
- 作業はスマートフォンのみ。PCは使えない
- 修正は差分ではなくファイル全文で出す（ただし index.html は約150KBあるため、変更箇所のみの提示とする）

## 8. 過去に見つかった落とし穴

- **「同名セレクタを突き合わせて差0件」では統一を確認できません。**
  名前が違って同じ役割のものを見つけられないためです。実際、
  関数68個・クラス48個・id 20個が別名のまま残っていました
- **使われていないコードが複数残っていました。**
  `testNotification` `showPushToken` `copyPushToken`（学園前A）、
  `toggleNotify` 一式（生駒・BA。ボタンが存在せず押せなかった）。
  master 化の際に整理し、通知の切替は正式に使えるようにしました
- **生駒・BAは色の変数体系が別物でした**（`--label` `--note` など15個）。
  master 化で A系の体系に統一したため、紫系の色味は無くなっています

### 2026-08-25 に見つかったもの

- **`manifest.json` が5アプリで別物でした。** master の管理外だったためです。
  学園前Aだけアイコンが `raw.githubusercontent.com` の外部URLで、しかも2枚のみ。
  Cだけ「共有」のショートカットがありませんでした。→ `master-manifest.json` に統一
- **`share.html` の JavaScript が壊れていました。**
  学園前AとBAで、変数名 `APP_URL` が URL そのものに置換されており
  （`const https://silvaoo.github.io/... = "..."`）、構文エラーで
  **共有ボタンが一切動きませんでした。** 予備だけが正常でした。→ 雛形化して修正
- **生駒とCに `share.html` が無いのに、manifest から呼んでいました**（404）
- **生駒の `sw.js` の見出しコメントが「BAダイヤ」のまま**でした

いずれも「master の管理外にあるファイルは、いつのまにか崩れる」という同じ原因です。
そのため manifest.json / sw.js / share.html も雛形から作る方式に変えました。

## 9. 残っている課題

- **Android通知の不安定さ** … 5アプリが同じ住所（`silvaoo.github.io`）にあるため、
  Firebase が IndexedDB のキーを共有してしまう。根本解決は独自ドメイン。
  ただし1人1アプリの利用なら実害なし。**当面は様子見**
- **独自ドメインへの移行** … 移行すると全員の入れ直しが必要。機能が固まってから
- **時間外計算** … `shukkin-search-ikoma2` で試作予定。計算方法は未確定
- **別営業所への展開** … apps.json に足すだけで増やせる状態になっている
