### push のしかた（1行）

```
git add -A && git commit -m "変更内容 (by AIタケタニ)" && git push "https://x-access-token:<トークン>@github.com/silvaoo/<リポジトリ名>.git" HEAD:main
```

- `<トークン>` は GitHub の Personal access token（`ghp_` で始まる）
- **トークンをファイルやコミットに書かないこと**（GitHub に見つかると自動で無効にされる）
- 使い終わったら GitHub の Settings で失効させる

  （無ければ「更新履歴はまだありません。」と出る）

## 2. ダイヤ改正のやり方

**2026-10-01 の北大和Ｂ・Ｃで実際に通った手順。次もこのとおりでよい。**

### 差し替えるもの（この5つを最初に並べること）

1. **データ** `dia-<code>-<MMDD>.json` を置く（旧ファイルは消さない）
2. **出退勤表のPDF** `pdf/shift-table-<MMDD>.pdf`
3. **勤務系統表のPDF** `pdf/kinmu-keitou-<MMDD>.pdf`
4. **出退勤表の画像** `images/genpage-<MMDD>-N.jpg`
5. **スペシャル検索くんの控え**
   - `ALL_DIAS` の url を新ファイルに
   - `pdf/shift-table-<code>.pdf`、`pdf/kinmu-keitou-<code>.pdf`
   - `images/` は元リポジトリを見るので差し替え不要

### apps.json に書く

```
NEXT_REV   改正日（例 2026-10-01）
NEXT_JSON  ./dia-<code>-<MMDD>.json
PAGES2     改正後の画像の枚数
SW_DIA_LINE に新しい json を1行足す（圏外用）
```

これだけで**改正日になったら自動で切り替わる**。手動の差し替えは不要。

### データの作り方

PDFの文字をそのまま取り出すと**2段組みが混ざって読み違える**。

```
pdftoppm -jpeg -r 200 元.pdf out
→ 画像にして目で読む
```

画像を2枚に分けるときは、**割合で切らない**。表の縦罫線を検出して切る。

```python
dark=(画素<128)
colscore=dark.sum(axis=0)/高さ
罫線=[x for x in 範囲 if colscore[x]>0.55]
```

### 確認

```
1 改正日の前日 → 旧ダイヤ
2 改正日当日   → 新ダイヤ（番号の数が変わること）
3 旧キャッシュが残った状態 → 新ダイヤ
4 圏外 → 控えから新ダイヤ
5 実機のフッターで「ダイヤ ◯◯◯◯-◯◯-◯◯改正 ／ ◯番」を見る
```

## 3. 注意点（2026-10-01 の作業で Claude が実際に踏んだもの）

### ★ 関数を足したら、呼び出しを grep で確かめる

**2026-10-01 に3回あった。** 定義しただけで呼んでいないので動かない。

```
loadOtherDias   → 呼び出しが無く、他ダイヤが選べなかった
renderHeadRev   → 呼び出しが無く、見出しが古いままだった
```

置換したあとに必ず `grep -c 関数名` で2以上あることを見る。

### ★ 置換が失敗していないか確かめる

Python の置換は、文字列が1文字でも違えば何もしない。**「入れたつもり」が 2026-10-01 に4回**あった。

```
置換 → grep で入ったか確認 → 生成
```

### ★ 入力欄のある画面で「作り直す」処理を足さない

1文字打つたびに画面を作り直すと、**カーソルが外れて1文字しか打てない。**

```
穴埋めの番号入力、時間外のダイヤ番号 … 両方これで壊した
```

結果の部分だけ差し替える。入力中は触らない。

### ★ Service Worker

```
skipWaiting() を install で呼ぶ     ← 呼ばないと永久に切り替わらない
HTML は毎回ネットワークから取る      ← 控えを返すと古い画面が出続ける
起動時に reg.update() を呼ぶ         ← PWAは自動で確認しないことがある
```

これが無くて、2026-10-01 は**直したコードが端末に届かなかった。**

### ★ 横に並べない

端末の文字サイズ設定で溢れる。`minmax(0,1fr)` を付けても足りないことがある。

```
body に font-size を必ず置く    ← 無いと iPhone 17px / Android 16px で差が出る
text-size-adjust: 100%          ← iPhone が勝手に拡大する
```

### ★ その他

- 保存キーには `{{ID}}-` 接頭辞
- 全角括弧をコードに書かない（build.py が止める）
- 版番号は `version.txt`（master.html の置換は黙って失敗する）
- モーダルを足したら**重なり順を検査する**

## 4. 時間外の計算（確定済み）

```
評価時間(付いた分)     = 労働時間 と 拘束時間×0.8 の多いほう
評価時間(走らなかった分) = 拘束時間 × 0.8
時間外                = 付いた分 − 走らなかった分
```

公休出勤・追加乗務は走らなかった分が0。振替は走らなかった側を引く。
**会社の数字と一致することを2例で確認済み**（2026-09-08の38番、2026-09-09の73番+6番）。

### 上限の見張り

```
締め期間の時間外   90時間
直近3期間の時間外  240時間（180時間で注意）… 意味は未確定、様子見
締め期間の拘束     275時間（解放を抜いて合算）
1日の拘束         15時間（通し。休息4時間以上なら超えてよい）
```

## 6. スペシャル検索くんの機能

```
すべて        211番の早見表
いまの時間帯   これから出勤する人だけ（乗務中は出さない）
穴埋めを探す   埋められる番号を順番に
```

穴埋めの並び順:

```
同じダイヤ → 予備 → その他
  各々で 2連休の1日目 → 中間ダイヤ → シングル公休
    各々で 番号の若い順
```

既定は**同じダイヤだけ**。「予備や他のダイヤにも広げて探す」で全ダイヤに。

判定: 1日の拘束15時間（休息4時間で延長可）、前後の休息8時間以上
（または相手が中間ダイヤで解放4時間以上）
