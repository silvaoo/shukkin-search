### 版番号（sw.js の v◯◯）はアプリごとにバラバラでよい

学園前Ａ v223、Ｂ v206、Ｃ v207、生駒 v32、予備 v32 のように数字が揃っていないが、
**揃える必要はないし、揃えてはいけない。**

この番号の使い道は3つで、いずれも頭にアプリ名が付くため、アプリ同士は干渉しない。

```
ikoma-shukkin-v32    キャッシュの名前（古いのを消すときも自分の名前だけ見る）
ikoma-push-bar       通知バーを「この版では閉じた」と覚える印
'ikoma-' + v32       更新のお知らせの識別子
```

比べる相手は**同じアプリの前の版だけ**。他のアプリの番号とは一度も比較しない。
ダイヤ改正の切り替えは `NEXT_REV` と `meta.cycle` で動くので、版番号は無関係。

**無理に揃えると害がある。** 番号を飛ばすと、その版で通知バーを閉じた記録が無効になって
全員にまた出てしまい、「更新のお知らせ」も新しい版とみなされて通知が飛ぶ。
バラバラなのは、各アプリが別々に更新を重ねてきた自然な結果。そのままでよい。

### push のしかた（1行）

```
git add -A && git commit -m "変更内容 (by AIタケタニ)" && git push "https://x-access-token:<トークン>@github.com/silvaoo/<リポジトリ名>.git" HEAD:main
```

- `<トークン>` は GitHub の Personal access token（`ghp_` で始まる）
- **トークンをファイルやコミットに書かないこと**（GitHub に見つかると自動で無効にされる）
- 使い終わったら GitHub の Settings で失効させる

### 勤務データ（dia-*.json）の形

全アプリ同じ形。

```json
{
  "meta": { "name":"…", "code":"a", "repo":"…", "cycle":92,
            "baseDate":"2026-05-03", "baseDial":36, "revision":"2026-03-14" },
  "holidays": ["2026-01-01", …],
  "obon": ["2026-08-13", …],
  "dials": {
    "1": { "平": {"o":"5:30〜17:35","w":"9:54"},
           "土": {"o":"…","w":"…","n":"備考"},
           "日祝": null },
    "5": null
  }
}
```

- `o` … 出退勤時間 / `w` … 労働時間 / `n` … 備考（無くてよい）
- `null` … 公休（番号ごと、または曜日ごと）
- 曜日区分は **平・土・日祝** の3つだけ
- `cycle` … 番号の総数。`baseDate` のその日が `baseDial` 番、という基準で日々ずらす。
  **画面の上限はこの `cycle` で決まる**（apps.json の `MAX` は初期値にすぎない）

### ★ 分割勤務（中間解放）の並び

```
"o": "6:15 / 12:25〜17:21 / 21:07"
      出勤   解放開始  解放終了  退勤
"w": "5:18 / 3:33"
      前半    後半
```

**前半 = 出勤 → 解放開始、後半 = 解放終了 → 退勤。**
拘束時間と労働時間には差がある（休憩の控除とみられる。前半0〜52分、後半0〜95分）。
**分割勤務の表示を触るときは、必ず算術的に検算すること。**

### ★ 保存キーには必ず `{{ID}}-` を付ける

全アプリが同じ住所（`silvaoo.github.io`）にある。部屋番号（`/shukkin-search/` など）が
違っても、ブラウザは保存領域を**住所ごと**に分けるため、全アプリが同じ引き出しを共有する。

```js
localStorage.setItem('{{ID}}-my-dial', v);   // 正しい
localStorage.setItem('my-dial', v);          // 全アプリで混ざる
```

`localStorage` も `sessionStorage` も同じ。接頭辞を忘れると、
**別のアプリが書いた値をこのアプリが読んでしまい、原因の分かりにくい不具合になる。**

実例：2026-08-26、「引っ張って更新」の音を1回見送る印を `'ptr-sound'` という
接頭辞なしのキーで置いたところ、生駒で立てた印を学園前Ａが食べてしまい、
「アプリによって鳴ったり鳴らなかったり」する症状が出た。
Android通知が不安定なのも、根っこは同じ「住所の共有」。

### ★ 文字の大きさは倍率付きで書く（2026-10-03〜）

右上の「表示の設定」で文字の大きさを70%〜130%に変えられる。
そのため、CSS や style 属性の文字サイズは次の形で書く。

```

```

- **build.py が見張っている**。倍率なしを見つけると行番号を出して止まる

### ★ 本来のダイヤに乗るかは otBaseOf() で判定する（2026-10-09〜）

記録の `base` を直接読まない。公休出勤（指定公休を含む）と年休の日は、
保存されている `base` に関係なく「乗らない（none）」として扱う。

```

```

  86番も出て、「出勤は5:08」と本来のダイヤの時刻を案内していた
- 保存するときも、公出・年休なら `base` は `none` で残す
- 指定公休の日の今日の画面: 出るダイヤを大きく、本来のダイヤは取り消し線で薄く

## 5. 時間外の計算（確定済み）

```
評価時間(付いた分)     = 労働時間 と 拘束時間×0.8 の多いほう
評価時間(走らなかった分) = 拘束時間 × 0.8
時間外                = 付いた分 − 走らなかった分
```

公休出勤・追加乗務は走らなかった分が0。振替は走らなかった側を引く。
**会社の数字と一致することを2例で確認済み**（2026-09-08の38番、2026-09-09の73番+6番）。

### 上限の見張り

```
締め期間の時間外   90時間
直近3期間の時間外  240時間（180時間で注意）… 意味は未確定、様子見
締め期間の拘束     275時間（解放を抜いて合算）
1日の拘束         15時間（通し。休息4時間以上なら超えてよい）
```

## 7. スペシャル検索くんの機能

```
すべて        211番の早見表
いまの時間帯   これから出勤する人だけ（乗務中は出さない）
穴埋めを探す   埋められる番号を順番に
```

穴埋めの並び順:

```
同じダイヤ → 予備 → その他
  各々で 2連休の1日目 → 中間ダイヤ → シングル公休
    各々で 番号の若い順
```

既定は**同じダイヤだけ**。「予備や他のダイヤにも広げて探す」で全ダイヤに。

判定: 1日の拘束15時間（休息4時間で延長可）、前後の休息8時間以上
（または相手が中間ダイヤで解放4時間以上）
